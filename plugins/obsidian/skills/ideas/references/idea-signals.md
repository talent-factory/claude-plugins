# Idea Signals — Interpretation Guide

## Strong Signals (high priority)

### Wiki cluster with many entries
When a single topic has three or more wiki pages (tool, concept, comparison),
it represents genuine expertise.
→ Ideas in this area are credible and immediately actionable.

### GitHub repo with open issues but few recent commits
A repository has open issues and the last push was more than 60 days ago:
someone started but stopped.
→ Ask: why did it stall? What would it take to ship 20% of the original vision?

### The same request from two or more stakeholders
When notes from different clients or colleagues describe the same pain point —
even in different words — that is market signal, not coincidence.
→ Prioritise accordingly.

### Wiki log shows the same topic ingested three times in 30 days
If you have ingested three sources on the same subject recently, you are
tracking something valuable.
→ Trust your own pattern recognition — this is worth investigating.

## Weak Signals (lower priority — note but do not act immediately)

### Market trend without a corresponding wiki basis
The market is moving, but you have no existing knowledge or experience in the area.
→ Record under "Market Observations", not as a Quick Win.

### Stalled repository without issues
The project was abandoned without any reported problems.
→ Probably abandoned for a good reason. Reflect briefly before re-engaging.

### Single stakeholder mention
Only one person has raised a particular problem.
→ Follow up to determine whether it is a genuine need or an isolated request.

## Anti-Patterns (avoid)

- **FOMO ideas**: "Everyone is doing X." Without existing expertise or
  clear stakeholder demand, ignore.
- **Infrastructure gold-plating**: "I could rebuild Y from scratch, better."
  Almost always a poor return on investment.
- **Feature-creep on stalled repos**: Adding new features to an unfinished
  project instead of shipping what already exists.

Replace this section with a brief description of your organisation's known
strengths, active customer industries, and recurring gaps that generate ideas.
This context makes the `/ideas` skill significantly more targeted.

Example structure:
```markdown
## Organisation Context

**Known strengths:** [domain A, domain B, tech stack]
**Active customer industries:** [industry A, industry B]
**Known gaps:** [recurring unmet need A, recurring unmet need B]

**Idea categories:**
- **Product ideas** (sellable): must address ≥ 3 customers, maintainable solo
- **Tool ideas** (open source): solves own problem + others', low opportunity cost
- **Learning projects**: only when there is a clear path from learning to applying
```
